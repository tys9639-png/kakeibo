# 家計簿

ブラウザだけで動く、1ファイル完結の家計簿アプリです。
記録はクラウド（Supabase）に保存され、**パソコンとスマートフォンで同じデータが見られます**。

## 使い方

公開URLをブラウザで開き、家族共有のアカウントでログインします。
スマートフォンでは「ホーム画面に追加」しておくと、アプリのように全画面で開けます。

`index.html` をローカルで直接開いても同じように動きます（同じクラウドに繋がります）。

### データの保存先

| どこ | 何が入るか |
| --- | --- |
| クラウド（Supabase） | 記録の本体。ログインした端末すべてで共有されます |
| 端末のブラウザ | 直前に同期した内容の控え。オフラインでも表示できます |

ログインせずに **「この端末に保存されたデータだけで使う」** を選ぶと、クラウドに繋がずその端末だけで使えます。

### 同期の仕組み

- 記録を追加・編集・削除すると、少し待ってから自動でクラウドに送られます
- 画面右上に状態が出ます（**同期済み** / 未同期 / 同期中… / 同期できません / この端末のみ）
- 別の端末での変更は、**タブを開き直したとき**と **⟳ ボタン**で取り込まれます
- 通信に失敗しても入力は端末に残り、繋がったときに自動で送り直されます
- 2台で**同時に同じ記録を編集した場合は、後から送られたほうが残ります**（家庭内での利用を想定した割り切りです）

### バックアップ

クラウドに置いていても、大事な記録は「データ」タブから CSV に書き出しておくことをおすすめします。
サービスを乗り換えるときも、CSV でそのまま持ち出せます。

## 画面

| タブ | できること |
| --- | --- |
| 入力・一覧 | 日付・種別（支出／収入）・カテゴリ・小カテゴリ・品目・利用者・支払い方法・金額・メモを入力して記録。その月の明細を一覧表示・**編集**・削除、種別／利用者／支払い方法での絞り込み |
| 集計 | カテゴリ別支出のドーナツグラフ（クリックで小カテゴリ→品目と2段階の内訳）、直近6か月の収入／支出の棒グラフ、利用者別・支払い方法別の支出、月別サマリー表 |
| 予算・カテゴリ | カテゴリごとの月予算の消化状況と小カテゴリ内訳。カテゴリ／小カテゴリ／品目／利用者／支払い方法の追加・名前変更・削除、予算額の設定 |
| データ | カード明細CSVの取り込み、店名の振り分けルール、家計簿形式CSVの書き出し・読み込み、全データの削除 |

画面上部の `‹` `›` で月を移動します。棒グラフの月をクリックしてもその月に移動します。
右上の ◐ ボタンはテーマ切替（ダーク → ライト → OS設定 の順に切り替わります）。

## カテゴリの階層

カテゴリは **カテゴリ › 小カテゴリ › 品目 の3階層** です（例：食費 › 食料品 › 野菜）。

- 下の階層は「予算・カテゴリ」タブの各行にある **＋小カテゴリ** / **＋品目** から追加します
- 入力時の小カテゴリ・品目は任意です。下の階層を持たない場合は選択欄が無効になります。
  小カテゴリを選ばないと品目も選べません
- **月予算は最上位のカテゴリにだけ設定します。** 小カテゴリと品目はその内訳として、
  予算バーの下とドーナツグラフのドリルダウン（2段階）で確認します
- 名前を変えると、下の階層とその記録も自動で追従します
- **小カテゴリ・品目を削除しても記録は消えません。** 1つ上の階層の直下に移ります
  （小カテゴリを消すと、その下の品目は削除されます）
- **最上位のカテゴリを削除すると、下の階層と記録もまとめて消えます**（削除前に確認が出ます）

## 利用者・支払い方法

「誰の支出か」「何で払ったか」を記録するための項目です。どちらも同じ作りで、既定値は次のとおり。

| 項目 | 既定の選択肢 |
| --- | --- |
| 利用者 | 豪 / 美夏 / 心葉 / 家族 |
| 支払い方法 | DC CARD / docomo D Card / d払い / 引落 / 現金 |

- 入力時はどちらも任意です（未選択なら「未設定」）。前に選んだものが次の入力にも残ります
- 明細一覧は利用者・支払い方法それぞれで絞り込めます（併用可）。絞り込むと見出しに
  その条件の支出・収入の合計が出ます
- 「集計」タブに **利用者別の支出** と **支払い方法別の支出** が並び、その月の金額・構成比・件数が出ます
- 追加・名前変更・削除は「予算・カテゴリ」タブのそれぞれのカードから
- 名前を変えると既存の記録も追従します。**削除しても記録は消えず、その項目が「未設定」になります**

## カード明細の取り込み

クレジットカードや電子マネー、銀行の利用明細CSVを、**列を画面で対応づけて**取り込みます。
各社でフォーマットが違うため決め打ちにはせず、どの形式でも読めるようにしてあります。

手順は「データ」タブで3ステップ。

1. **ファイルを選ぶ** — 文字コード（UTF-8 / Shift_JIS）は自動判定。読み込んだ中身がそのまま表になって出ます
2. **列を対応づける** — 見出し行・日付の列・金額の列・店名の列を選びます。
   多くの場合は自動で当たるので、色が付いた列（青＝日付／橙＝金額／緑＝店名）が合っているか見るだけで済みます。
   併せて 支払い方法・既定のカテゴリ・利用者・金額の符号（支出が正か負か）を指定します
3. **取り込む内容を確認して実行** — 実際に入る記録が一覧で出るので、確認してから取り込みます

補足:

- **一度設定すると支払い方法ごとに記憶され、次回は自動で復元されます**（毎月の明細は選ぶだけ）
- **同じ明細を二重に取り込みません。** 日付・金額・店名・支払い方法が既存の記録と一致するものは自動で飛ばすので、
  期間が重なるCSVをそのまま入れて構いません
- 取り込むのは **支出のみ**です。逆符号の行（入金・返金・キャンセル）と、日付か金額が読めない行は対象外になります
- 日付は `2026/8/3` `2026-08-03` `2026年8月3日` `20260803` `8/3`、金額は `1,280` `¥1,280` `▲500` `(1,200)` `１２８０` を解釈します

## 店名の振り分けルール

取り込んだ記録は店名しか分からないので、**店名キーワード → カテゴリ** のルールで自動的に振り分けます。

- 例：`セブン` → 食費 › 食料品、`AMAZON` → 日用品
- 上の行から順に判定し、最初に一致したルールを使います（`↑` で優先度を上げられます）
- 一致しなかった記録は、取り込み時に指定した「既定のカテゴリ」になります
- ルールを増やした後で **「既存の記録にも適用する」** を押すと、過去の記録もまとめて振り分け直せます
  （書き換わる件数を出して確認します）

振り分けきれなかったものは、明細一覧の **編集** ボタンから直接直せます。

## 家計簿形式の CSV

このアプリ自身の書き出し・読み込みに使う形式です（バックアップや表計算ソフトとの受け渡し用）。
カード明細を入れたい場合は、上の「カード明細の取り込み」を使ってください。

列は次の順で、1行目の見出しは省略できます（見出しがある場合は自動で読み飛ばします）。

```
日付,種別,カテゴリ,小カテゴリ,品目,利用者,支払い方法,金額,メモ
2026-08-05,支出,食費,食料品,野菜,美夏,DC CARD,1280,スーパー
2026-08-07,支出,ローン,住宅,,家族,引落,78000,住宅ローン
2026-08-25,収入,給与,,,,,280000,
```

- 日付は `YYYY-MM-DD`
- 種別は `支出` または `収入`
- 小カテゴリ・品目・利用者・支払い方法は空欄で構いません（小カテゴリが空なら品目も無視されます）
- 金額は正の整数（円）。`1,280` や `¥1280` のような表記も読み込めます
- 列の少ない旧形式もそのまま読み込めます。見出し行があればそれで、なければ列数で判定します
  （9列＝全部あり、8列＝支払い方法なし、7列＝小カテゴリ＋利用者、6列＝小カテゴリのみ、5列＝どれもなし）
- 読み込んだデータは既存データに **追加** されます（置き換えではありません）
- CSV にあって未登録のカテゴリ・小カテゴリ・品目・利用者・支払い方法は自動で作成されます
- 形式に合わない行は読み飛ばし、件数を画面に表示します
- 書き出しは Excel でそのまま開けるよう UTF-8 (BOM付き) です

## 仕様メモ

- 外部ライブラリ・CDN はゼロ。グラフは素の SVG を組み立てて描いています。
  クラウドとの通信も、SDK を使わず REST API を直接叩いています（1ファイルのまま保つため）
- HTML に書かれている Supabase の URL と `anon` キーは公開前提の値です。実際の保護は
  ログインと RLS（行レベルセキュリティ）が行い、新規登録は閉じてあります
- カテゴリ別グラフは金額上位7件まで色分けし、残りは「ほか N 件」にまとめます（内訳表示でも同じ）
- 予算バーの色は状態のみを表します（80%以上でオレンジ、超過で赤 + 「予算超過」表示）
- カテゴリは内部的に「先祖の名前の配列（path）」で保持しているので、階層を増やす改造は
  `LEVEL_NAMES` と記録側の項目を足すだけで済みます
- 以前の形式（階層なし／2階層／利用者なし）で保存したデータもそのまま読めます
